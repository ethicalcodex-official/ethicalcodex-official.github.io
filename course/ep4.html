DNS: The Internet Phonebook & Reconnaissance

Humans remember domain names; computers route packets using numerical IP addresses. Understand the full resolution hierarchy and how to query DNS records for target reconnaissance.

1. How DNS Resolution Works

When you type a website URL into a browser, a hierarchical lookup takes place across four types of DNS servers:

  1. DNS Recursive Resolver: The first stop (often managed by your ISP or public resolvers like Cloudflare 1.1.1.1 or Google 8.8.8.8) that tracks down the record for you.
  2. Root Nameserver (.): Directs the resolver towards the Top-Level Domain (TLD) nameservers based on the domain extension (.com, .org, .io).
  3. TLD Nameserver: Holds details for all domains under that specific extension and refers the resolver to the domain's authoritative nameserver.
  4. Authoritative Nameserver: The final authority that holds the actual DNS records and returns the corresponding IP address to the resolver.

Common DNS Record Types

  • A Record: Maps a hostname to an IPv4 address.
  • AAAA Record: Maps a hostname to an IPv6 address.
  • CNAME (Canonical Name): Creates an alias pointing from one domain name to another.
  • MX (Mail Exchanger): Directs incoming email traffic to the domain's mail servers.
  • TXT (Text): Holds text data, frequently used for email security verifications (SPF, DKIM, DMARC) and domain ownership verification.

2. DNS Reconnaissance with Linux Commands

Use the standard dig (domain information groper) utility to perform fast, flexible DNS lookups:

BASH — Quick A record query for IPv4 addresses 
dig +short google.com
BASH — Query mail server (MX) records for a domain 
dig google.com MX +short
BASH — Check TXT records for SPF and verification strings 
dig google.com TXT +short
BASH — Inspect authoritative nameservers with nslookup 
nslookup -type=ns google.com
