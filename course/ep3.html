TCP vs UDP & The 3-Way Handshake

कनेक्शन ओरिएंटेड बनाम कनेक्शनलेस प्रोटोकॉल। SYN, SYN-ACK, ACK की वर्किंग और हैकर्स इसका कैसे विश्लेषण करते हैं।

💡 सुरक्षा तथ्य: Nmap का सबसे प्रसिद्ध डिफॉल्ट स्कैन -sS (SYN Stealth Scan) इसी 3-वे हैंडशेक के आखिरी ACK पैकेट को न भेजकर RST भेज देता है, जिससे फुल कनेक्शन नहीं बनता!

1. TCP और UDP में मुख्य अंतर

ट्रांसपोर्ट लेयर (L4) पर दो प्रमुख प्रोटोकॉल काम करते हैं:

  • TCP (Transmission Control Protocol): भरोसेमंद (Reliable), कनेक्शन-ओरिएंटेड। यदि कोई पैकेट गिर (drop) जाता है, तो यह उसे दोबारा भेजता है। (उपयोग: Web Browsing HTTP/S, SSH, File Transfer).
  • UDP (User Datagram Protocol): तेज़ (Fast), कनेक्शनलेस, कोई गारंटी नहीं। (उपयोग: Live Streaming, VoIP, Online Gaming, DNS Queries).

TCP 3-Way Handshake की कार्यप्रणाली

क्लाइंट और सर्वर के बीच डेटा ट्रांसफर शुरू होने से पहले 3 कदम होते हैं:

  1. 1. SYN (Synchronize): क्लाइंट सर्वर से कहता है - "नमस्ते, क्या मैं आपसे पोर्ट 80 पर कनेक्ट हो सकता हूँ?" (Seq=X)
  2. 2. SYN-ACK: सर्वर जवाब देता है - "हाँ, मुझे आपका अनुरोध मिला, मैं तैयार हूँ।" (Ack=X+1, Seq=Y)
  3. 3. ACK (Acknowledge): क्लाइंट अंतिम पुष्टि करता है - "ठीक है, कनेक्शन स्थापित हो गया। अब डेटा भेजते हैं।" (Ack=Y+1)

2. व्यावहारिक Linux सॉकेट कमांड्स

अपने लिनक्स सिस्टम पर कौन से पोर्ट्स TCP या UDP पर सुन (Listen) रहे हैं, यह जांचें:

BASH - सभी लिसनिंग TCP और UDP सॉकेट्स देखना 
ss -tuln

* -t = TCP, -u = UDP, -l = Listening, -n = Numeric ports (no DNS lookup).

BASH - कौन सा प्रोसेस पोर्ट चला रहा है (PID सहित) 
sudo ss -tulnp
