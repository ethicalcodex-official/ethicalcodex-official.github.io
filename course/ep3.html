TCP vs UDP & The 3-Way Handshake

Discover how reliable connections are established over the internet, how SYN floods and stealth port scans exploit connection states, and how to monitor sockets in Linux.

1. Key Differences Between TCP and UDP

Both protocols operate at Layer 4 (the Transport Layer) of the OSI model, but they are built for entirely different trade-offs:

  • TCP (Transmission Control Protocol): Connection-oriented and reliable. Before any data payload is sent, a 3-way handshake is completed. If a packet is lost during transmission, TCP automatically requests a retransmission. (Used by: HTTP/HTTPS web traffic, SSH, SFTP, email).
  • UDP (User Datagram Protocol): Connectionless and fast. Packets are fired towards the recipient without establishing a state or waiting for acknowledgment. Packets that drop are ignored. (Used by: DNS lookups, video streaming, VoIP voice calls, multiplayer gaming).

The TCP 3-Way Handshake

Every successful TCP session begins with a three-step greeting sequence between the client and server:

  1. Step 1: SYN (Synchronize): The client sends a packet with the SYN flag enabled and an initial sequence number (e.g. Seq=X) asking to establish a connection on a specific port.
  2. Step 2: SYN-ACK: The server replies with both SYN and ACK flags enabled (Seq=Y, Ack=X+1), indicating it is ready to communicate.
  3. Step 3: ACK (Acknowledge): The client sends an ACK packet (Ack=Y+1) confirming receipt. The connection is now in the ESTABLISHED state, and application data transmission begins.

2. Practical Linux Socket Commands

Use the modern ss (socket statistics) utility to inspect open connections on your machine:

BASH — List all listening TCP and UDP sockets in numeric format 
ss -tuln

* Flags breakdown: -t for TCP, -u for UDP, -l for listening sockets, and -n to show numerical port numbers instead of resolving service names.

BASH — Show process IDs (PID) owning each open port (requires root) 
sudo ss -tulnp
