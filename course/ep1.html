IP Addresses, Classes & Subnetting Fundamentals

Every device connected to a computer network needs an identifier. Understand IPv4, IPv6, private vs. public IP ranges, and how to inspect network interfaces in Linux.

1. What is an IP Address?

Just as physical mail requires a unique postal address to reach the correct destination, digital devices on a computer network require a logical identifier called an Internet Protocol (IP) Address to send and receive packets.

As an ethical hacker or security analyst, identifying target IP addresses and determining whether they are internal (private) or external (public) is always one of the very first reconnaissance steps.

IPv4 vs IPv6

  • IPv4 (32-bit): Written as 4 decimal octets separated by dots (e.g. 192.168.1.1). It supports approximately 4.29 billion distinct addresses, which is no longer enough for all connected devices worldwide.
  • IPv6 (128-bit): Written as 8 hexadecimal groups separated by colons (e.g. 2001:0db8:85a3::8a2e:0370:7334). It provides an astronomical address space (around 340 undecillion addresses).

Public vs Private IP Addresses

Public IP addresses are globally unique and routable across the public internet. Private IP addresses are reserved for internal local area networks (LANs) and cannot be routed across the public internet directly.

The standard private IP address ranges defined by RFC 1918 are:

  • 10.0.0.0 – 10.255.255.255 (Class A range)
  • 172.16.0.0 – 172.31.255.255 (Class B range)
  • 192.168.0.0 – 192.168.255.255 (Class C range, common in home routers)

2. Practical Linux Commands

Open your Linux terminal (or Kali Linux VM) and run these commands to inspect your network configuration:

BASH — View network interfaces and assigned IP addresses 
ip -c a
BASH — Check the default gateway (your local router IP) 
ip route show default
BASH — Check your public IP address from the command line 
curl -s https://api.ipify.org
BASH — Test connectivity to an external host with 3 ping packets 
ping -c 3 8.8.8.8
